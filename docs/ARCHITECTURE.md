# Architecture

CLI and MCP adapters call the same Engine. SQLite WAL with BEGIN IMMEDIATE serializes mutations; task source+external key is unique. Runs use random fencing tokens, time-limited leases and immutable task/policy/controller snapshots. Heartbeats cannot exceed total run budget. Repo-level active lease prevents two tasks mutating one checkout. Expired attempts are closed and requeued on the next claim. Crashes leave durable state recoverable after expiry.

queued → running → changed → verifying → verified → ready_review → accepted. accepted means local acceptance for review, never released. failed/expired attempts retain history. No arbitrary state update or publish endpoint. Verification invokes only project-approved argv commands in a clean child process with a restricted environment, captures output, and compares source digests before/after. Acceptance recomputes source digest. Worker commands never update policy. Configuration is frozen at database creation and runs pin it again. Workflow source digest identifies the controller and every attempt mutation enforces that it equals the run’s pinned digest; dogfooding uses physically separate frozen controllers. State and evidence live outside source digest under .workflow.

This is cooperative local enforcement, not an OS sandbox: a same-user worker can alter database, frozen controller or tests. Trust reviewers must inspect diffs. No untrusted source text becomes command, policy, permissions or credentials. GitHub/Discord/X adapters, release and origin replies are future work. An optional single-concurrency local runner already launches separately budgeted worker/reviewer processes; its source, policy, credentials and scheduling role remain distinct from MCP. MCP is a tool interface, not a scheduler.

Default pull selection skips exhausted attempts while explicit claims retain a clear budget error. Verification atomically enters `verifying`; worker mutations are blocked until the command returns or its lease expires. Commands run in a new POSIX session with a timeout bounded by the starting lease, run deadline and test budget. Timeout kills the process group and reaps its direct child. Subsequent commands are skipped once the cutoff has passed. Completion under valid ownership may update the task; expired completion only stores machine evidence on its original run and emits `verification_expired`, preserving a recovered successor. Verification-start events expose crashes, and expired in-flight runs are eligible for recovery.

Process groups provide cooperative cleanup rather than OS isolation. A separate POSIX guardian starts first; a gated process cannot exec the approved argv until its group is acknowledged. A parent-only pipe signals verifier death by EOF, and the guardian also enforces the fixed command/lease cutoff. An exec-error pipe closes on successful exec and otherwise preserves original OSError launch evidence (exit 127). A deliberate new session or a killed guardian can escape cleanup; database lease recovery does not establish zero overlap at the scheduling boundary. Non-POSIX descendant cleanup has not been validated. Output drain threads retain at most 65,536 raw bytes per stream and exact totals/truncation metadata.

The runner records bound process execution intents, startup/idle/total cutoffs and terminal guardian observations; unconfirmed recovery fails closed. Versioned exec observations do not grant task completion. Controller-collected receipts bind complete Git diff manifests, task/run/base/candidate, Core machine evidence, independent review artifact, executed versions and completed CAS. The whole package and trusted Python/helper files are fingerprinted. Read-only metrics aggregate fixed configured parent goals with duplicate protection and version/raw-log validation; they distinguish historical claims, unknown evidence, backend sessions and local subprocesses. No same-user hash or fixture proves hostile-worker isolation or a new external agent success rate.
